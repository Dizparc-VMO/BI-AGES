# Architecture Decision Records

Add a numbered kebab-case Markdown record for significant changes to ownership,
data boundaries, platform selection, contracts, or deployment strategy. Start
with `0001-` and increment without renumbering existing records. This starter
contains guidance only, not customer-specific approved decisions.

Each record should include:

- Title, date, status (proposed, accepted, superseded), and decision owner.
- Context, requirements, constraints, and affected companies/shared consumers.
- Decision and alternatives considered, including reasons for rejection.
- Consequences for security, costs, compatibility, operations, and testing.
- Migration, deployment, rollback/forward-recovery, and related references.

Keep accepted decisions traceable; supersede them with a new linked record rather
than rewriting history. Use synthetic examples and never include secret values.
