# Power Automate

Store reusable Power Automate flow sources and solution guidance here. Keep
company-specific triggers, policies, and connector bindings under
`companies/<company>/power-platform/power-automate/`.

Document each flow's owner, purpose, trigger, inputs/outputs, connectors, data
classification, company scope, run-as identity, dependencies, licensing, and
support path. Use solution-aware flows, environment variables, and connection
references where supported. Test retry and timeout behavior, concurrency,
idempotency, duplicate events, failure notifications, and sanitized run history.
Never rely on a maker's personal connection as production ownership. Document
target binding, permissions, smoke tests, and recovery for every environment.
